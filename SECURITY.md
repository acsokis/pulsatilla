# Security policy

Security heuristics are review indicators, not proof of an attack or a guarantee of protection.
Use scans only on networks where you are authorized to run them.

Report reproducible software issues with synthetic inputs, affected version and Windows version.
For a sensitive vulnerability, use the repository's private vulnerability reporting feature
when enabled. Do not post exploit details, watched addresses, captured traffic or personal logs
in a public issue. If private reporting is unavailable, ask for a private reporting channel
without disclosing the vulnerability publicly. No private contact address has been invented here.

The maintainer should enable private vulnerability reporting after creating the GitHub repository.
Review the latest tagged release first; no paid support SLA or response time is promised.
